## 人格化陪伴MCP（2026-09-08）
云端数字分身为独立普通用户和虚拟设备cloud-agent-2323485，不复用宠物身份。桥接进程将固定设备和每次连接新会话写入受控环境，工具参数不可指定身份。除十个共用工具，云端额外提供memory_search/add/forget与emotion_support；候选记忆由独立账号在App审批，个人上下文向MiniMax出站已获用户明确授权。云端端点令牌仅见服务器cloud.env。

工具新增conversation_plan、context_search、companion_reply、interaction_feedback、shared_activity、followup_plan。数据接口唯一真源为backend docs/06的companion小节。
本地私有配置companion_tools_enabled开启时，在每次系统提示装配中加入工具选择与失败规则；该开关显式透传全模块配置。讲故事、说笑话、陪聊由对话模型直接完成，不必等待联网工具；若误调用娱乐工具且失败，改口自己讲，不说素材失败。运势与文化解读必须等待对应联网工具成功，不将策略计算误报为联网检索。

对aipet_music_content连接，小智从conn.device_id/session_id构造X-Companion-Device/X-Companion-Session，并从私有business_api.token构造X-Companion-Token，覆盖同名静态头。MCP恒时比对token后才调用backend，身份不进入模型工具参数。未认证的请求不得读取档案或执行反馈/约定写入，错误不暴露其他设备是否存在。

context_search保存180秒、最多128条的临时检索证据；search_id只在同设备同会话可用。companion_reply可以消费一次已有search_id；无search_id时娱乐陪聊不再强制检索。运势/玄学仍须真实检索，失败不纯生成回退。策略计算与持久化不需要额外LLM调用。

旧daily_chat用于故事/笑话/闲聊时跳过联网；生成先走 MiniMax，不可用（额度/鉴权/超时/未配置）时回退火山方舟 DeepSeek-V4-Flash，仍失败才提示对话模型自己讲。星座/玄学优先 MiniMax 检索，检索服务不可用时同样回退方舟且不得声称已联网。方舟密钥只在服务器 content.env / companion.env，不入库。feedback保存candidate，提示用户审核；followup保存不等于发送或完成。到期只在合适在线会话带出，08:00至21:00东八区，不实现离线唤醒。源码、服务端与物理验收分别记录。

## BLE 偶遇社交（E9，未实现）

该能力不是由 App/智控台发起配对，也不是本仓建立双机实时会话桥。设备在户外通过低速 BLE
匿名广播发现对方，主动询问主人；双方同意后才交换短期 token。之后每只设备各自通过控制通道
上报，本仓仅做设备消息到 backend HTTP 契约的鉴权转发和失败降级：

| 设备侧动作 | backend HTTP | 本仓职责 |
|------------|--------------|----------|
| `social.encounter.report` | `POST /api/internal/devices/{device_uid}/social/encounter-reports` | 注入可信 `device_uid`、转发对端 token 与同意时间；不记录 token |
| 查询本侧结果 | `GET /api/internal/devices/{device_uid}/social/encounter-reports/{report_id}` | 只向报告所属设备返回状态及其可播放内容 |
| 播放回执 | `POST /api/internal/devices/{device_uid}/social/encounter-reports/{report_id}/ack` | 转发 `played|failed`，保持幂等 |

backend 负责匹配双方报告和生成本次内容；本仓不得把 A 的实时 ASR/LLM/TTS 输出注入 B，不存
偶遇业务真源，也不自行生成双方对话。完整草案以 backend `docs/06`、`docs/11` 为准。

当前阻塞是设备空闲时语音 WS 已关闭，尚未确定用哪条常驻控制通道承载上报、结果通知/轮询和
播放触发。控制通道未统一前只允许做协议与转发层 spike，不实现依赖“已有语音 WS 在线”的假链路。
本地 BLE 偶遇询问与 E11 远程主动播报是两个触发源，但可在未来复用同一受控下行通道。

### 实现位置（V0.2）

- 旁路模块：`main/xiaozhi-server/core/business_report.py`（单例 FIFO 队列+有界重试，4xx 丢弃、5xx/网络错误指数退避，上限可配）；重试在独立旁路线程内完成，后续 `chat/events` 不会越过 `devices/seen`，`session/end` 也不会越过尚在重试的消息。连接建立先入队 `devices/seen`，保证后续事件的设备已建档。
- 智控台导入：`core/console_device_sync.py`。进程启动即初始化旁路（不再等首个 WS）。优先 `POST /config/bound-devices`（manager-api，server secret）；未部署该端点时回退读智控台 MySQL `ai_device`。同一 MAC 本进程只导入一次，避免把未连 WS 的设备刷成在线。
- 挂钩：`core/handle/reportHandle.py` 的 `enqueue_asr_report`/`enqueue_tts_report`（独立于 manager-api 上报，不受 `chat_history_conf` 影响）；会话结束挂在 `core/connection.py close()`，三处均使用连接原生 UUID `session_id`。眼睛 MCP 成功后由 `UnifiedToolHandler` 更新快照并上报外设状态。
- 开关：`data/.config.yaml` 的 `business_api` 段（`enabled/base_url/token/timeout/max_retry`），manager-api 不下发，由 `config/config_loader.py` 透传

## Context Provider（backend 已上线；小智侧 b8 已接入，2026-08-16 容器级验收通过，待真机验收）

小智上游 Context Provider 不是 MCP/RAG：它只在唤醒、构建 Prompt 时请求一次外部
HTTP 数据，并把短摘要替换到 `{{ dynamic_context }}`。backend 路由已实现，不得把已有
`persona_pack` 当作该接口。

backend 已定稿并实现（契约见其 `docs/06`）：

| 方法 | 建议路径 | 鉴权与输入 | 成功响应 |
|------|----------|------------|----------|
| GET | `/api/internal/context/device` | `X-Internal-Token`；上游自动发送 `device-id`（MAC） | `{"code":0,"data":["短摘要", "..."]}` |

- 未知设备、无 persona 或无上下文均应返回 `200` + 空 `data`，不阻塞首轮语音。
- `data` 仅含至多 6 条、约 800 中文字符以内的已发布 KB/已审核记忆/当日分析摘要；
  不含完整 KB、原始对话、敏感字段或内部 ID。
- backend 不得在此同步路径调用 LLM 或 worker，目标 P95 小于 300ms；小智侧超时
  上限 0.5 秒并降级为空上下文（实测 C5 响应 7ms）。
- token 只放本地容器配置或部署密钥，不写入智控台、仓库和协作看板。
- 本仓最终 Prompt 合并已修复（b8）：`persona_pack` 不覆盖 `{{ dynamic_context }}`。

## Memory MCP

- 业务仓部署 `memory-mcp`，生产传输已定为 **streamable HTTP MCP**：受控 Docker 内网的 `http://memory-mcp:8000/mcp`；不得走公网或使用 stdio+mcp-proxy 桥接。
- 每个请求必须带 `X-Internal-Token`；工具只传规范化 `device_uid`（MAC/SN），不得传平台自增 `device_id`。
- 挂载白名单固定为 `memory.search` / `memory.add` / `memory.forget`；检索可带 `retrieval_hints`。
- 调用超时预算 800ms～1.5s；401、网络失败、5xx、MCP 协议异常一律降级为无记忆会话，不阻塞 ASR/LLM/TTS。

### 实现位置（V0.2 / b10）

- 客户端与执行器：`core/providers/tools/memory_mcp/`（JSON-RPC POST，backend `stateless_http` + `json_response`，无需 MCP session）。
- 挂钩：`UnifiedToolHandler` 在服务端 MCP 之后初始化；失败只降级，不阻断语音。
- 开关：`data/.config.yaml` 的 `memory_mcp` 段（`enabled/url/timeout/max_retry`）；`token` 缺省复用 `business_api.token`，manager-api 不下发，由 `config/config_loader.py` 透传。
- LLM 侧工具名是 `memory_search` / `memory_add` / `memory_forget`（点号已清洗）；调用时强制注入连接 MAC，丢弃模型传入的 `device_id`。
- `memory.search` 在模型未显式提供 `retrieval_hints` 时，自动合并当前 `persona_pack.retrieval_hints` 到检索 query；模型显式参数优先。
- 日志走 `integration_log`（tag=BIZ，op=`memory_mcp` / `memory_mcp_list`），只记工具名、状态、耗时、`device_uid`、`session_id`，不记记忆正文或 token。

### `blink_profile` 能力边界

`persona_pack.blink_profile` 当前保留在七字段契约中，但目标固件仅提供单次眨眼和自动 idle 开关，尚无运行时设置眨眼间隔/时长的 MCP 工具。本仓不得在设备未执行时宣称配置已生效；待固件增加对应能力后再由本仓按设备 `tools/list` 结果选择性下发，旧固件继续忽略该字段。

## 失败策略

| 失败 | 策略 |
|------|------|
| 拉 pack 失败 | 用缓存；无缓存用安全默认；会话仍继续 |
| pack 返回 404（设备未配置人设） | 用内置引导人设（onboarding 文案，供稿待定） |
| 旁路写入失败 | 本地重试队列，**不阻断** TTS |
| Memory MCP 失败 | 对话继续，仅无长期记忆 |

## 2026-11-17 BLE 触摸测试协议 v1（限定 COM7/COM25）

契约已变更：当前测试用专用 128-bit UUID 的 BLE Service Data 广播互认两台固定测试身份，版本 1，角色 1=COM7、2=COM25；与白名单设备映射，不宣称通用认证名片。payload 26 字节：UUID[16]、version[1]、role[1]、invite_nonce LE32[4]、target_role[1]、state[1]、reserved[2]；state=0发现、1邀请、2接受。Flags 加 Service Data 共 31 字节。仅 COM7 触摸可生成新 nonce，邀请/接受有效期 20 秒、附近窗口 6 秒，重复邀请不重复启动，COM25 白名单测试自动接受。首次遇见写 NVS，后续只刷新 RAM；当前不广播用户资料。此为测试广播控制协议，不是正式 GATT 名片/授权实现。

双方按同一 invite_nonce 打开现有认证 WS，发送 type=social_test,state=join,invite_id=8位小写十六进制；无普通唤醒开场白。COM7 仅在一轮彩虹完成后 join，COM25 自动接受后 join。小智按认证连接 MAC 校验两台白名单、同 nonce 双方入场（20 秒）、TTS 就绪和空闲状态，幂等创建已有双真房间；任意设备不能指定另一个 MAC。未匹配/过期会结束等待，设备 25 秒兜底退出。测试采用固定身份映射，正式社交仍需名片认证与双触摸。
