# 03 — 会话智能体与人设注入

## 原则

- **人设真源在业务库**；本仓只做「运行时加载」。  
- 禁止在通话中全量检索知识库改写人设（R8）。  
- pack 来自业务 `PersonaCompiler` 的**已发布/钉扎版本**。  
- 服务固定基础行为（当前 `pet_default`）只约束简洁、动作、打断与事实边界；星座、
  MBTI 和用户个性仍只来自业务 `persona_pack`。

## 推荐集成方式（按易到难）

### 方式 A：会话开始 HTTP 拉取（首选）

```text
设备 hello / 新会话（并按 `persona_refresh_interval` 定时刷新，默认 300 秒）
  → xiaozhi-server 用 device_id 调业务 API
  → GET /internal/devices/{id}/persona_pack
  → 与固定基础行为合并进当前智能体 system Prompt
  → 开始 ASR→LLM→TTS
```

### 方式 B：智控台模板 + 业务回写

- 业务变更人设后，调用本仓管理 API 更新智能体配置（若上游支持）。  
- 注意避免与业务库双写冲突：以业务 API 为真源，本仓仅缓存。  

### 方式 C：薄人设（V0.1）

- 智控台手工贴一段星座或 MBTI 模板 Prompt，不调业务。  
- 仅用于通路验证。  

## Prompt 组装顺序（当前线上）

```text
pet_default（服务固定行为）
  → persona_pack（backend 动态星座/MBTI 人设）
  → Context Provider 短摘要（已上线 b8，2026-08-16 容器级验收通过，待真机验收）
```

智控台“角色介绍”仍可作为配置保留，但不得覆盖该最终顺序，否则会重新引入冗长或
与用户人设冲突的本地角色设定。

## persona_pack 最小字段（约定）

```json
{
  "kb_version": "2026.07.26-water.3",
  "system_prompt_fragments": ["..."],
  "style_constraints": ["..."],
  "taboo": ["..."],
  "default_emotion": "gentle",
  "blink_profile": "slow",
  "retrieval_hints": ["feelings", "relationship"]
}
```

- `default_emotion`：首次成功拉取和后续 pack 发生变化时，可由本仓发 MCP `self.eye.set_emotion`。
- 完整编译逻辑见 `ai-pet-backend/docs/03-人设与星座知识库.md`。  

## 验收

- [ ] 业务改为双鱼+INFP 后，新会话口吻可辨（盲测）  
- [ ] 钉扎 kb_version 的设备不随运营发布突变  
- [ ] 业务 API 超时有降级（沿用上次缓存或安全默认人设，并打日志）  
- [ ] 已连接设备修改人设后，最多一个刷新周期内新 Prompt 生效，不重复执行未变化 pack 的眼睛动作
